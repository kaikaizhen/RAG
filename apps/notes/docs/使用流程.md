# 使用流程：從記筆記到用 RAG 問答

開新專案、每天記筆記、整理筆記、同步到 RAG、在 RAG 問問題，照這份做就好。

```
寫程式 → Claude 用 MCP 記筆記 → notes.doraeyi.com 看筆記
                      ↓ npm run sync:rag
              RAG 自己的 Space → rag.name404.com 問問題
```

## 一、每台電腦只要設定一次

### 讓 Claude 能記筆記

到筆記網站的「Token」頁產生自己的 token。指令在自己的終端機執行，token 不要貼進對話或任何 repo：

```bash
claude mcp add --transport http --scope user learning-notes https://notes-api.doraeyi.com/mcp --header "Authorization: Bearer 你的token"
```

設定好後開新的 Claude 對話，它就會用筆記工具，也知道筆記的規則（白話、不編原因、不放機密）。

### 讓這台電腦能同步到 RAG

只有要手動同步的電腦才需要。在 RAG repo 的 `apps/notes` 資料夾建立 `.env`（不會進 git）：

```
NOTES_MCP_URL=https://notes-api.doraeyi.com/mcp
MCP_TOKEN=你的token

RAG_API_URL=https://rag.name404.com
RAG_ACCOUNT=你的RAG帳號
RAG_PASSWORD=你的RAG密碼
```

`.env.example` 是範本，會進 git，**不要把真的值填在那裡**。

## 二、開始一個新專案

不用先建立任何東西。第一次記筆記時，Claude 會用 `add_entry` 自動建立專案和模組。

1. 開始時跟 Claude 說專案名稱，例如「這是預約系統，模組是實驗設備預約」。
2. 第一次記錄時，回應裡的 `project_created` 會是 true。確認名稱沒打錯，否則之後會分散在兩個專案。
3. 專案名稱會出現在 RAG 的問答裡，取一個之後問問題時會用到的名字。

## 三、平常怎麼記

筆記分成四種，Claude 會依內容選擇：

| 種類 | 什麼時候用 | 工具 |
| --- | --- | --- |
| 改動紀錄 | 每完成一次程式改動 | `add_entry` |
| 一般筆記 | 不是程式改動的學習整理，例如「ERP 從訂單到出貨怎麼串」 | `save_article` |
| 觀念卡 | 遇到看不懂的名詞，例如「BU」「攤提」 | `save_concept` |
| 規則 | 模組現在的商業規則，例如「同時段只能預約一台」 | `update_project_rules` |

**改動紀錄**

- 改完程式後，Claude 會問要不要記一筆。你同意才會寫入。
- 「為什麼」要是你說過的理由。Claude 不知道時會問你，不會自己編。
- 測試狀態照實際情況：沒測就是「沒測過」。
- 標題寫成之後會想搜尋的句子，例如「黑名單擋預約」。RAG 是用標題比對的，標題寫得好，之後比較容易問到。

**一般筆記**

- 一定要屬於某個專案，才會跟著專案的分享範圍同步到問答。同一個專案裡，標題一樣就是同一篇，再存一次會覆寫。
- 標題寫成別人會問的樣子，例如「ERP 從訂單到出貨怎麼串」。內文可以用「## 小標」和「- 條列」分段。
- 單一名詞的解釋還是用觀念卡；一般筆記適合把好幾個觀念串起來的長篇整理。

**觀念卡、規則和一般筆記都要標可信度**

- 一般定義：查得到的通用意思。
- 從程式推測：自己看程式猜的。**沒問過人的商業規則一律是這個**。
- 已向同事確認：要寫向誰確認。

不懂的地方寫進觀念卡的「還不懂的」，之後可以請 Claude 列出所有待確認的問題，一次去問同事。

**不能放進筆記的**：密碼、連線字串、token、email、真實個資。系統會擋大部分，但姓名、電話這類要自己注意。

## 四、整理筆記

| 想做的事 | 跟 Claude 說 | 工具 |
| --- | --- | --- |
| 改正寫錯的內容 | 「entry#5 的原因寫錯了，改成…」 | `update_entry` |
| 刪掉重複或記錯的紀錄 | 「刪掉 entry#1」 | `delete_entry` |
| 更新觀念卡 | 「更新『BU』這張卡」 | `save_concept` |
| 更新或刪掉一般筆記 | 「把 ERP 那篇補上 MRP」「刪掉那篇重複的筆記」 | `save_article`、`delete_article` |
| 刪掉重複的觀念卡 | 「刪掉『RAG 回答方式』這張卡」 | `delete_concept` |
| 規則不再適用 | 「預約系統的『舊規則』不適用了」 | `update_project_rules` |

- 改動紀錄是專案的歷史。之後又改了程式就**另記一筆**，不要拿 `update_entry` 覆寫舊的。
- 刪除無法復原。Claude 會先給你看內容，你同意才刪。

## 五、看筆記

https://notes.doraeyi.com ，用問答系統（RAG）的帳號密碼登入，每個人只看得到自己的筆記。網頁只能看，要改請透過 Claude；在「Token」頁可以產生自己的 MCP token。

## 六、同步到 RAG

平常不用手動同步：在「分享範圍」頁設定好，背景同步每分鐘會處理（見下面的「分享範圍」）。下面是手動同步的做法，在 `apps/notes` 資料夾裡執行，第一次要先 `npm install`。

**一定先預覽**，這一步不會寫入任何東西：

```bash
npm run sync:rag -- --project 專案名稱
```

看「新增、更新、刪除、不變」的數字合不合理，沒問題再加 `--apply`：

```bash
npm run sync:rag -- --project 專案名稱 --apply
```

- **送什麼由 `--project` 決定**。可以寫多次，例如 `--project A --project B`。不加就是全部筆記。
- **筆記會存到朋友的 RAG 伺服器**。公司專案要想清楚再送。
- 改了或刪了筆記之後，再跑一次就會更新 RAG：改過的會更新，刪掉的會從 RAG 刪掉，沒指定的專案不會被動到。
- 自己在 RAG 手動新增的問答不會被動到。只有答案最後一行有「來源：learning-notes …」的才歸同步程式管。
- 想把 RAG 上**其他專案**的筆記也清掉（例如之前送過的公司筆記），加 `--prune`：只留下這次 `--project` 指定的專案。一樣先預覽，確認要刪的筆數再加 `--apply`。
- 讀筆記時一次 50 筆、自動翻頁讀完。筆記服務是舊版不支援翻頁時，會顯示可能沒讀到全部，這次就不會刪除任何東西。

### 分享範圍（誰問得到）

到筆記網站的「分享範圍」頁，每個專案選一種：

| 範圍 | 意思 |
|---|---|
| 只留在筆記 | 預設值，不會離開筆記主機 |
| 我的問答 | 同步到自己的 Space，只有自己問得到 |
| 公開 | 寫進公開 Space，所有登入的人都看得到、問得到 |

背景同步每分鐘處理有變動的人。改回不分享時，內容會從問答系統移除。公開前系統會掃描整個專案，有疑似 email、密碼或 token 就不讓公開；公開的內容不會帶「向誰確認」的人名。

### 問答答不出來時

按回答下方的「交給筆記」，確認後問題會出現在待確認頁。Claude 用 `list_knowledge_gaps` 看得到，補成筆記後用 `resolve_knowledge_gap` 關閉，下次問答就答得出來。

## 七、在 RAG 問問題

1. 打開 https://rag.name404.com 並登入。
2. 確認左上角是同步時的 Space。同步時畫面會印出 `RAG Space：…`，例如「liam 的空間」。
3. 直接問。

**RAG 怎麼回答**：它把你的問題和每筆筆記的標題比對，算出 0 到 1 的相似度。

| 相似度 | 回答方式 |
| --- | --- |
| 0.7 以上，而且明顯比第二名高 | 直接回那篇完整筆記 |
| 0.5 到 0.7 | 把最相關的幾篇接起來，太長就截斷，結尾是「…」 |
| 0.5 以下 | 找不到足夠可靠的內容 |

**怎麼問比較準**

- 用筆記標題裡的詞。例如問「把後端部署到 VM」，相似度是 0.98；問「筆記怎麼部署的」，只有 0.54。
- 帶上專案名稱，例如「預約系統的黑名單怎麼擋」。
- 一次問一件事。

**之後會變好的地方**（等朋友合併後才有）

- RAG 會用 LLM 讀相關筆記，直接回答你的問題，不再接原文。模糊的問題也能答得好。
- 摘要上限從 500 字提高到 2000 字。
- 回答最後的「來源：learning-notes entry#2」會變成小標籤。

## 八、遇到問題

| 狀況 | 原因和處理 |
| --- | --- |
| Claude 沒有筆記工具 | 這台還沒跑第一節的 `claude mcp add`，或要開新對話 |
| Claude 看不到新工具 | 伺服器更新後要開新對話 |
| 同步說要設定 NOTES_MCP_URL | `apps/notes` 資料夾沒有 `.env`，或在錯的資料夾執行 |
| 同步出現 401 | `MCP_TOKEN` 或 RAG 帳號密碼不對 |
| RAG 回答被截斷、結尾是「…」 | 相似度不到 0.7，改用標題裡的詞再問 |
| RAG 說找不到 | 確認 Space 對不對、那個專案有沒有同步過 |
| 伺服器程式更新了 | 合併到 RAG 的 `main` 後，在主機上 `git pull`，到 `apps/notes` 執行 `docker compose up -d --build` |
